# イベントの定期的な追加（public/data/events.json）

月 2 回（1 日・15 日）、クラウドの Claude（ルーティン「ホテル予報: イベントの追加」）がこの手順で大型イベントを追加し、`main` に push して公開する。
人が手で追加する時も、同じ決まりに従う。

## 何を追加するか
- 期間: 実行した日から約 4 か月先までに開催されるもの（アプリの予報は約 3 か月先まで。少し先まで入れておく）
- 対象の都市: `src/cities.ts` の 61 都市（`id`）。会場が対象の都市の外なら載せない（例: エスコンフィールド＝北広島、Aichi Sky Expo＝常滑、エコパ＝袋井）。幕張メッセは `chiba`
- 大きさ: 1 日あたりおよそ 8,000 人以上が集まるもの。プロスポーツのふだんのリーグ戦は載せない（開幕カードなど特別なものだけ）
- 種類（`category`）: `live`（ポップス・ロック・アイドルの公演）、`fes`（音楽フェス）、`concert`（クラシックなど）、`sports`、`expo`（展示会・即売会）、`festival`（祭り・季節の行事・入試など）

## 確かめ方（いちばん大事）
- **公式の発表で、日付と会場を自分で見たものだけを載せる**（会場の公式スケジュール、主催者・アーティストの公式サイト、公式のプレスリリース）
- まとめサイト・検索結果の抜粋・報道だけで、公式で確かめられないものは載せない。推測で日付を入れない
- 「PRIVATE」「貸切」「関係者のみ」は載せない
- すでに載っているものは、日程の変更・中止が公式に出ていれば直す・消す

## 形式
```json
{"id": "kebab-case-unique-id-2027", "city": "tokyo", "start": "2027-02-13", "end": "2027-02-14",
 "venue": {"ja": "東京ドーム", "en": "Tokyo Dome"}, "title": {"ja": "…", "en": "…"},
 "category": "live", "scale": 2, "url": "https://確かめた公式のページ"}
```
- `scale`: 1 = アリーナ級（1 日 8,000〜2 万人）、2 = ドーム・スタジアム級や大きな展示会（3〜6 万人）、3 = 街じゅうが埋まる特別なもの（10 万人以上。さっぽろ雪まつり、東京マラソン、コミックマーケット など）
- 連続した日程は 1 件にまとめる（`start`〜`end`）。離れた日程は別の件にする
- 同じ会場は、すでにある件と同じ会場名（ja・en）を使う
- 英語の題は公式の英語名、なければ短い訳
- 配列の最後に、開始日の順で足す。整形は `JSON.stringify(data, null, 2)`（インデント 2・日本語はそのまま）

## 仕上げ
1. `npm ci` のあと `npm test`（`src/eventsData.test.ts` が形式・都市・日付・重複を確かめる）と `npm run build` が通ることを確かめる
2. 追加・変更があれば、`public/data/events.json` だけをコミットして `main` に push する（GitHub Actions が公開する）。コミットメッセージは日本語で、例: `イベントを追加（2027年4月分 23 件）`
3. 追加がなければ、何もコミットしない
4. 最後に、追加した件数（月ごと・種類ごと）、公式の予定がまだ出ていなかった会場、確かめられずに見送ったものを報告する
